# hakira-cloud-project — Phase 2 会计复式记账核心业务测试报告

> **阶段：** Phase 2 · 会计复式记账核心业务
> **状态：** ✅ 已通过

---

## 一、测试范围

| 测试项 | 内容 |
|--------|------|
| 分录录入 | 借贷平衡分录、不平衡分录 |
| 分录查询 | 按 ID 查询、按条件搜索 |
| 库存入库 | 首次入库、多次入库 |
| 库存出库 | 正常出库、超量出库 |
| 库存快照 | 快照查询、流水查询 |

## 二、测试环境

| 项目 | 值 |
|------|-----|
| 系统 | Ubuntu VM |
| JDK | openjdk 21.0.11 |
| 存储 | 内存（ConcurrentHashMap，本阶段） |

## 三、测试用例与结果

| 用例 | 预期 | 结果 |
|------|------|------|
| 借贷平衡分录录入 | 成功，返回 POSTED | ✅ |
| 借贷不平衡分录 | 拒绝（500 + 错误信息） | ✅ |
| 按 entryId 查询分录 | 返回完整分录 | ✅ |
| 按科目搜索分录 | 返回匹配分录 | ✅ |
| 入库 10 件 | 快照 = 10 | ✅ |
| 出库 5 件 | 快照 = 5 | ✅ |
| 超量出库 | 拒绝「库存不足」 | ✅ |
| 快照查询 | 返回当前库存 | ✅ |
| 流水查询 | 返回入出库流水 | ✅ |

## 四、问题与处理

| 问题 | 根因 | 处理方案 | 结果 |
|------|------|---------|------|
| 借贷不平衡返回 HTTP 500 | 用 IllegalArgumentException 抛出，无统一处理 | Phase 5 引入全局异常处理器，返回业务错误码 1001 | ✅ 后续解决 |
| 库存不足返回 500 | 同上 | Phase 5 统一为业务错误码 1002 | ✅ 后续解决 |

## 五、结论

Phase 2 会计复式记账核心业务完成，分录借贷平衡校验、库存入出库 + 快照 + 流水全部可用。本阶段异常以 500 返回，Phase 5 统一为业务错误码。内存存储方案在 Phase 5 替换为 MySQL 持久化。
