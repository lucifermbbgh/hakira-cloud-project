## 一、阶段目标

实现会计复式记账核心业务：**分录服务（entry）** 与 **库存服务（stock）**，建立「凭证录入 → 借贷平衡 → 分录记录」「入库/出库 → 库存核算」两条核心业务链路。

## 二、阶段范围

| 服务 | 模块 | 职责 |
|------|------|------|
| 分录服务 | `hakira-ledger-entry` | 分录录入、查询、搜索，借贷平衡校验 |
| 库存服务 | `hakira-ledger-stock` | 入库、出库、库存快照、流水查询 |

## 三、复式记账核心规则

| 规则 | 说明 |
|------|------|
| 有借必有贷 | 每笔分录至少一方借方、一方贷方 |
| 借贷必相等 | 借方合计 = 贷方合计，不等则拒绝 |
| 分录结构 | 头（汇总）+ 行（明细），支持一借多贷/一贷多借 |

## 四、业务接口设计

### 4.1 分录服务（`/entry`）

| 接口 | 方法 | 功能 |
|------|------|------|
| `/entry/post` | POST | 录入分录（借贷平衡校验） |
| `/entry/{entryId}` | GET | 按 ID 查询分录 |
| `/entry/search` | POST | 按日期/科目/状态搜索 |

### 4.2 库存服务（`/stock`）

| 接口 | 方法 | 功能 |
|------|------|------|
| `/stock/inbound` | POST | 入库（增加库存） |
| `/stock/outbound` | POST | 出库（减少库存，超量拒绝） |
| `/stock/snapshot/{itemCode}` | GET | 查询当前库存快照 |
| `/stock/movements/{itemCode}` | GET | 查询库存流水 |

## 五、设计要点

| 要点 | 决策 |
|------|------|
| 存储方案 | 本阶段先用内存存储（ConcurrentHashMap），Phase 5 换 DB |
| ID 生成 | 雪花ID（20位：日期时间戳 + 随机数） |
| 业务校验 | 借贷不平衡/库存不足用异常拒绝（Phase 5 统一为业务错误码） |

## 六、阶段验收标准

- [x] 分录录入/查询/搜索可用
- [x] 借贷平衡校验生效（不平衡拒绝）
- [x] 库存入出库 + 快照 + 流水可用
- [x] 超量出库拒绝
